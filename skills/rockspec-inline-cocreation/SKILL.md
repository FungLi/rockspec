# inline 共创（能力单元）

这是 BA / SA **首次无产物**时共享的交互纪律。角色 skill 引用本能力，只补充**自己产出什么产物、什么才算开放决策**。共享结构引用 [rockspec-glossary](../rockspec-glossary/SKILL.md)。

## 何时走 inline 共创

仅当**首次、该产物尚不存在**时，你在主会话戴角色帽子与用户交互式澄清/设计。产物已存在被驳回 → 走 [rockspec-isolated-rework](../rockspec-isolated-rework/SKILL.md)，不再共创。

## 共创四步

1. **静默读证据**：从磁盘读输入产物（proposal / approved requirements）和相关仓库证据（现有架构、约定、依赖），不靠聊天记忆。
2. **识别真正开放的决策**：只有你角色 Authority 范围内、答案无法从已表达意图和既有规则确定的开放决策才需要问用户。最多把三个相关决策合并成**一个 Decision Package** 一次性展示（决策问题、候选方案、推荐及理由、影响、风险、不选的后果），然后结束回复等待用户。无开放决策则直接静默写完整份产物。
3. **只更新受影响决策**：用户回答后只更新被影响的部分，**不**把目标/范围/规则/正常路径/失败行为拆成章节逐条向用户确认。次要细节用有依据的保守假设写进产物，交制衡者核验，不占用用户。
4. **落定即交棒**：产物落盘 Ledger（`rockspec conclude` 计算 output_hash）后，由 PM **折叠对话**——丢弃澄清过程细节，主会话只留一条骨架，后续回看从 Ledger 读产物。

## 共创不豁免制衡

inline 共创出的产物照样交制衡者独立评审。PM 折叠后调度的制衡者是**真正独立的隔离实例**，绝不复用共创上下文。共创让方向对齐用户，制衡保证质量，两者不互相替代。
