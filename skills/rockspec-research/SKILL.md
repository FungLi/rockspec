# RockSpec 业务研究

## 产物语言

读取 `.rockspec/config.yaml` 的 `artifact_language`；缺省按 `zh-CN`。面向人的调研正文、结论和终端摘要使用配置语言，Schema Key、ID、Action、CLI 和规范关键字保持英文。

只产出一个结果：足以支持下一项业务决策、且每个重要结论都可追溯的研究基线。

## 边界

- 这是探索与研究，不是 Requirements、Design 或实施。可以读取仓库、文档、数据和外部来源，但不得修改产品代码或自动创建 Change。
- 研究编排与用户协作保持 Inline：确认决策、拆分问题、选择研究路径和形成结论的主线留在主循环，不拆给后台 Subagent。事实由 Agent 查找，业务决策由用户作出；不得把可自行查证的问题转交给用户。
- 只读事实检索可外包：可自行查证、且**只读、单次、无需用户 Authority** 的批量检索或跨来源核对（读仓库、文档、数据、外部资料以确定既有事实），派只读 Subagent 完成，主上下文只保留结论和来源锚点，不保留检索过程。判据是「只读 + 单次 + 不替用户作业务决策」；任何需要用户拍板的业务问题都不外包，也不转交给用户以外的 Agent 代为拍板。
- 研究产物是有时间边界的输入，不是永久事实。来源过期、业务变化或样本不足时必须重新验证。

<INTERACTIVE-GATE>
这是在线协作能力，不是一把生成报告的文档任务。当前问题、研究路径或报告章节尚未得到用户确认时，必须结束当前回复并等待；不得写入最终 `research.md` 或 `receipt.yaml`，不得宣告研究完成，不得启动 Reviewer，也不得进入 Requirements 或其他下一能力。用户确认会话中的研究内容，不替代后续 Change 的任何绑定 Hash 审批。
</INTERACTIVE-GATE>

## 执行

严格按以下顺序执行：

1. 静默从磁盘读取已有 PRD、Spec、研究、领域词汇、产品行为、指标定义、支持或销售材料；能从环境、仓库或来源查证的事实自行查证，不把它们变成用户问卷。
2. 与用户确认研究要支持的决策、目标受众、范围、时间边界和停止条件。问题过宽时先帮助拆分；每条消息只问当前最重要的一个问题，提问后结束回复并等待。
3. 提出 1 至 3 条真实可行的研究或证据路径，先给推荐及依据，再说明覆盖面、成本、可靠性和停止条件。只有一条合理路径时说明约束，不虚构选项。用户选择前不得开始收集该路径的证据。
4. 按选定路径静默收集证据。优先使用内部一手数据和记录、用户或领域专家原始陈述、官方文档、法规/标准、源代码和第一方产品资料；二手资料只作为线索，重要主张回到拥有该事实的来源。
5. 使用 `FACT`、`USER_REPORT`、`INFERENCE`、`HYPOTHESIS`、`UNKNOWN` 标记重要结论，并记录来源、时间、适用范围和置信度。将来源矛盾并列展示，不通过平均或措辞掩盖冲突。
6. 在会话中依次展示并确认：现状与角色；术语、流程、规则与冲突；有证据的洞察及其解释；未知、机会、结论与建议。每次只展示一个章节，明确询问是否准确；用户未确认时结束回复并等待，收到纠偏后先修订当前章节再继续。简单研究可以合并为一个短章节，但不得跳过确认。
7. 只有全部章节确认后，才从 [research-report.md](assets/research-report.md) 写入 `.rockspec/workbench/research/<slug>/research.md`，生成带来源时间和可选 Change 关联的 `receipt.yaml`，并重新读取产物检查遗漏、矛盾、无来源主张和过度推断。执行前读取 [research-protocol.md](references/research-protocol.md)。
8. 当研究问题已有可行动答案、重要主张有证据、矛盾已显式化、剩余未知有负责人或验证方式，且继续收集不再可能改变当前决策时停止。无法满足时输出 `MORE_RESEARCH_NEEDED` 或 `BLOCKED`，不得无限扩张。

报告研究状态、问题与决策、证据覆盖、业务现状、术语与规则、洞察、矛盾、未知和建议下一步。报告写入后询问用户是否进入 Requirements，并结束回复等待选择；只有用户明确决定进入研发时，才将报告交给 `$rockspec-requirements`。研究结论不能替代 Spec Approval。
